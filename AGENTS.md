# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

## What this is

- Sound Blaster Command for Linux: a GTK 4 / libadwaita control panel (Rust 2024) for the Creative Sound Blaster ZxR (CA0132), modelled on Creative's Windows app. Public at https://github.com/ImZoomBoy/soundblaster-command-linux, GPL-3.0-or-later (except `driver/`, which is GPL-2.0-only kernel code).
- The developer's machine: ZxR at PCI `0000:67:00.0` (`1102:0012`, subsystem `1102:0010`, ALSA card id `Creative`), Cambridge SoundWorks DTT2200 5.1 speakers, CachyOS (clang-built kernel), KDE Plasma, PipeWire + WirePlumber.
- Module map, features and install steps are in [README](README.md). The UI is the full-window **page** design (prototype rounds 53–101, `docs/redesign-build.md`): what's playing fills the window (background art printed in the page red, the room drawn by a theme, title block top left, big 5.1 or the live venue top right, the cover, and the sound choices Where / Room / Tone / Extras in a slim dock, rows or a sport-style bar), with the controls dock bottom right. The old output / SBX / EQ cards live in the **Sound** side panel; Mixer, CrystalVoice, Speaker setup, Settings and **Look and feel** are side panels too. There is no header bar (the design never had one): ☰ (bottom right) opens the **control centre**, and the window buttons sit at the top right, always shown except in the Strip (they used to fade in only when the pointer came near; the user couldn't reach them, 2026-10-30). Every window size must look good in every theme (user, 2026-10-30: "no matter what size the window i resized to"). The window shows one of four views (a `gtk::Stack`, `Ui::on_window_size`): the page (1200+ wide and 600+ tall); **half a screen** (the page at 900–1200 wide, 600+ tall, e.g. Meta+Left on a 1920 screen: each theme its own layout, round 125, see below); for windows under 900x600 or the Compact theme the **Remote** or **Over your shoulder, mini** (`Settings.compact_view`); the **Strip** under 300 px tall (dragging a window down ends there and carries on to 76 px; the Remote can't be shorter than about 270 px), or from the control centre's "The Strip" (1240x76), with its own short ☰ menu and minimise/close group. Remote and Strip are `mini.rs` (prototype rounds 102–112, `~/Downloads/sbcommand-designs/compact-round1xx.html`).

## Build and test

- `cargo build --release`, `cargo test` (unit tests), then the GUI self-test, always inside the isolated screen: `dev/isolated-kwin.sh "$PWD/target/release/sbcommand selftest"` (38 checks; prints `INFO first frame after N ms` separately from freeze checks). It fails on any GTK warning or critical: a size warning ("Trying to measure ... but it needs at least") repeats in the journal for as long as a layout is wrong (the user saw thousands from the half-screen title block). Measure a widget for a width with `stage::height_at` (never below its least width; margins count in GTK's sizes). The test screen keeps the graphics driver's shader cache between runs in `~/.cache/sbcommand-test/glcache` (as the desktop does); with an empty cache (the first run or two, or after a driver update) GTK compiles its shaders mid-test and the freeze check can fail: run it again.
- Screenshots for `docs/screenshots`: `dev/screenshots.sh` (dry run, fictional demo media from `assets/demo`, rebuilds `hero.png`).
- `SBCOMMAND_DRYRUN=1` prints card writes instead of making them; `SBCOMMAND_CONFIG_DIR` points settings elsewhere; `SBCOMMAND_SHOT=file.png`, `SBCOMMAND_SHOT_SIZE=WxH`, `SBCOMMAND_SHOT_PATH`, `SBCOMMAND_DEMO_MEDIA=music|movie|game`, `SBCOMMAND_DEMO_ART` drive screenshots.
- Install for the user: `./install.sh` (binary to `~/.local/bin/sbcommand`, `sbcommand-watch` user service, desktop entry, the icon as SVG plus fixed PNG sizes from `packaging/icons`).
- The icon (`packaging/com.local.sbcommand.svg`, the user's pick in round 122, `~/Downloads/sbcommand-designs/icons-round122.html`) is "SB" bent into red neon on black (round 122; the user tried a white neon speaker and a red one first); its glow is layered strokes, because KDE draws SVG icons without filters (blur). It is installed under its own name (`main::ICON`, now `com.local.sbcommand-sb`, also in the desktop entry, the tray and notifications; `install.sh` removes the old names): KDE keeps icons by name in memory and never notices a new file under an old name, so a new icon needs a new name. Re-render the PNGs with `rsvg-convert` when it changes; the symbolic icon is the same SB as filled shapes (symbolic icons are recoloured by their fill). After installing, restart `sbcommand-watch` and reopen the app; check that no PipeWire/WirePlumber restart happened (`systemctl --user show -p ActiveEnterTimestamp pipewire pipewire-pulse wireplumber`).
- `GSK_RENDERER` must be `gl` (the old `ngl` name caused a 455 ms freeze). The test screen uses the NVIDIA GPU, so the first frame takes about 1.3 s there; that is not an app freeze.

## Safety rules (from incidents; do not relax)

- Never start a test KWin (or any Qt/KDE session process) on the user's session bus or with their config folders. It took over their keyboard shortcuts once. Use `dev/isolated-kwin.sh` only, and afterwards check that `~/.config/kglobalshortcutsrc` and `~/.config/kwinrc` mtimes are unchanged. Never screenshot the real desktop.
- Never play sound on the real speakers without the user's go-ahead. A load test once played a tone on them. Prefer silent checks: `dev/where-is-each-channel.sh` (null sink) and reading the card sink's `.monitor` with `parec`.
- Never restart `pipewire`, `pipewire-pulse` or `wireplumber` without asking (it cuts browser audio). The app only rewrites their config files when the text changes.
- Card resets (`systemctl start soundblaster-reset-now.service`) cut sound for a few seconds; say so first.
- Commit or push only when asked. Commits use the user's GitHub no-reply identity.

## Hardware and audio facts

- 5.1 channel order: the ZxR's DSP takes Windows order, so the 5.1 sink is `audio.position = FL,FR,FC,LFE,RL,RR` (WirePlumber rule written by the app). The driver's own chmap says the same. Do not change it.
- ZxR outputs: front L/R on the two RCA sockets; rear L+R on one 3.5 mm socket (DTT2200 black plug); centre+sub on another 3.5 mm socket (orange plug). The DTT2200 subwoofer unit splits them to separate satellite jacks.
- The driver forces SBX X-Bass off whenever a subwoofer is configured, so the app applies Bass through the card EQ. Bass redirection sends every channel's bass to the sub: a 60 Hz tone on the front-left channel coming out of the sub proves the sub path works.
- **Silent centre/sub/rear right after a card start (root cause found 2026-10-27):** after each DSP start (boot, wake, reload, reset) the DSP can miss the start-up state of converter amps 0x03 (centre L / LFE R) and 0x04 (surround L/R) and output exact zeros on any mix of FC, LFE and RR. It only applies those amps on a change, and the HDA amp cache skips unchanged writes. Fixes: the app's `card::wake_surround()` toggles Center/LFE/Surround Playback Switch off and on after every card appearance (watch loop), and the driver patch's `zxr_wake_outputs` mutes and restores the amps 1.5 s after start-up (end of `ca0132_init()` is too early). Each alone gave 8/8 good starts. It is random per start, not warm-vs-cold: a power-off only seemed to help. A card reset now brings a silent speaker back; don't tell the user to power off.
- To check the DSP outputs without listening: `capture/dsp-probe.sh` (needs `capture/debug-helper.sh`; `QUICK=1` gives a one-line verdict). It plays six quiet tones and records each DSP output through the What U Hear router entries. Its readings matched the user's ears.
- Speaker tests must be multichannel files that are silent except on one channel (`system::spread_to_channel`). A one-channel "FC" stream gets copied to FL+FR by PipeWire, which sounds like a centre speaker (phantom centre) even when the centre is dead; that hid a silent centre for days. Stock ALSA voices are quiet, so tests are normalised to -1 dBFS. For the sub, steady 60-80 Hz tones are audible; the rumble file is fainter.
- `speaker-test -s N` does not follow the card's chmap; use `aplay` with a prepared 6-channel file instead.
- `driver/zxr-fixes.patch` is the product patch for `snd-hda-codec-ca0132`: the delayed amp re-send above (per-card delayed work, cancelled on suspend/remove, re-armed on resume) and three bass-redirection crossover bugs (wrong variable, 10 Hz off by one, out-of-bounds at 100). `driver/dev/zxr-debug.patch` (test-only, `sh driver/build.sh --dev`) adds the root-only `zxr_debug` hook that `capture/` needs, plus experiments (off by default). Regenerate patches with `diff -u` against `driver/build/ca0132.c.orig`, and check that `zxr-fixes.patch` then `dev/zxr-debug.patch` apply in order. See [driver/README](driver/README.md).
- The stock driver reloads the X-Bass crossover into the card whenever it redoes the output setup (speaker setup, Output Select, the effects master switch), so the app writes the crossover last in every batch with a neighbouring value first (`model::crossover_pairs`).

## Sharp edges in the code

- The page: `stage.rs` (widgets only), `ui/page.rs` (a child module of `ui`, so it uses `Ui`'s private fields: what kind of content, the four sound choices and what each changes, the room scene, the game monitor and full screen, the Look and feel panel), `oys.rs` (the Over your shoulder room), `themes.rs` (Blueprint, Screenprint, Callouts), `meta.rs` (content kind + pictures: TheAudioDB, Steam, Playnite, TMDB with a key), `art.rs` (the red print, auto levels), `fonts.rs` (Anton, Archivo Narrow and Archivo bundled, added for this process only).
- GtkPicture takes a picture's own size, so covers and logos are drawn by `stage::Art` (a DrawingArea) at the size wanted; only the full-bleed background uses GtkPicture (Cover fit).
- Hidden side panels still count towards the window's minimum width: their scrolled windows must allow sideways scrolling, or the window can't get small enough for the compact view. The side panels' column (an `AdwOverlaySplitView` sidebar) also asks for 125 px of height while hidden, so the Strip takes it out of the split view and puts it back after (`Ui::side_for`); `set_strip` does that before resizing, or the window stays 125 px tall.
- The control centre (rounds 102/113; the user rejected the List pop-up as small and size-changing): `side_box` in a `Revealer` overlay on `root_ov` with a dimming scrim, its size set ONLY from the window (`Ui::size_panel`, on `side_box`, which sits in a bar-less ScrolledWindow `cc_clip` so the panel asks for no size of its own: while a window shrinks, before `size_panel` catches up, GTK warned it got less than it needs; 520–660 x up to 820 above the dock; a small window fills below the window buttons). The pages sit in `side_stack`, each in a ScrolledWindow, so no tab or press can resize it (the stack isn't homogeneous: measuring only the tab shown keeps layouts quick). Tabs are pill ToggleButtons (no red line). **Every tab fits without scrolling** (the user: "too big if it requires vertical scrolling"), in the round 102 prototype's compact style: one-line rows (compact libadwaita rows via `.cc row > box.header` CSS, group titles as small caps), the Mixer's levels as rows with a meter under each slider (`level_row`, `dash::draw_hmeter`), Sound's five knobs in one row with their power light by the value, the EQ curve taking what height is left, the speaker test as a plan of buttons (`test_grid`), Settings' three repairs on one line, Look and feel as small pictures with "your defaults" as one sentence. The settings audit (round 117, all applied): no volume or headphones button in the Sound tab (the dock has them; mute moved into the dock beside the volume), no "Equaliser on" (Flat; a saved "off" migrates to Flat), the recording levels in the Microphone tab (the Mixer is speakers only), "Channels" for the speaker layout, Headphone gain only while on headphones, a speaker brand hides the switches it decides (`spk_info` says what it set), the Compact theme became `compact_always` ("In big windows too"), the Remote's top only when the Remote is picked, no Strip button or pin in Look and feel (the header and the Strip have them), the TMDB/Playnite rows only while pictures are looked up, no fixed card-info row. Room for a tab is about 515 px at 440x720 and 1240x800. Under 600 px wide `narrow_panel` shortens the tab names, shows the headphones button as an icon and slims the margins. The self-test checks every tab's least width and its height (games too: two lines of chips) against the panel at 440, 1240 and 1400 px, and prints `INFO control centre at WxH: tab need/room`. The first opening in a session compiles a few GTK shaders (~0.2 s on the NVIDIA card with an empty driver cache; the desktop keeps that cache). GtkOverlay doesn't measure overlay children, so it never sizes the window. A closed Revealer that crossfades keeps its full size and still takes clicks: ☰'s closed panel sat over five of the room's six speakers so they couldn't be clicked; `cc_rev` and `wctl` only take clicks while revealed (`can_target` follows `reveal-child`), and the self-test checks with `Window::pick` that a click on each speaker reaches the room. Toasts skip the Strip (AdwToastOverlay measures its toasts and would make the window taller); the views stack has no transition (during one, the outgoing view still counts towards the window's size); the "isn't responding" banner is an overlay too (AdwToolbarView added height).
- **Half a screen** (`Stage::set_half`, `stage::half_geo`, round 125 `half-round125.html`): the cover, credits, bio, facts, corner and ticket go; the four choices become tiles placed by the theme; the controls sit centred across the bottom. Over your shoulder: the room across the middle, glass tiles two by two over a dark controls band. The Remote's room shows the six speakers front on (`room::row`) once its box is over 3.2 times as wide as tall (`remote_row`), as in a 1400x400 window.
- The compact views (`mini.rs`) are widgets only: `Stage` forwards what the page gets (`set_head`, `set_cover`, `set_fields`, the background photo, `mirror()` for the controls) and their presses come back as the page's own actions ("act:pp", "pick:room:Concert"). The Remote draws its photo with its own DrawingArea (`Pic`): a GtkPicture asks for its whole height and squeezes the room. Its choices open a sheet from the bottom (Done or the dimmed window closes it); the Strip's open popovers that may reach past the 76 px window. The Strip's readout sits in its controls, as on the page. The Strip's pin is a KWin script loaded over D-Bus (`mini::pin_window`: keepAbove and onAllDesktops for the app id), KDE only.
- The dock's speaker button opens the full-screen **speaker test** (`ui/speaker_test.rs`, round 101's "Test your speakers"): the page's red photo behind a shade, the room in perspective (the prototype's `iso()` in a 1020x640 drawing, `draw_room` returns tap boxes for each speaker and its name), Walk round (front left round to the sub, 1.8 s apart), Noise (`system::make_noise`, pink) or Voice (`Settings.test_sound`); music pauses while it's open (MPRIS) and plays again after. `sbcommand speaker-test` opens it (screenshots).
- The game monitor's trailer is a GtkMediaFile, muted unless its sound button is on; full screen takes the same stream (it never restarts) and closing hands it back, muted. Only pressing play in full screen (or the monitor's sound button) makes sound; never in dry run / selftest.
- Tone (warmer / brighter) is a tilt added in `model::effective_eq` on top of the EQ preset (`TONE_WARMER`), not a preset.
- The page's layers are gtk::Overlay children, which never push each other. `Stage::fit_cover_room` (a 250 ms timer) measures the title block against what's below: the big cover shrinks to the space left, or moves by the title under 90 px; then the bio, then the full-screen button, are hidden until there's room again. Short compact windows (>= 700 wide, < 760 high) put the sound choices two to a line. The compact speaker plan is sized to end above `Stage::lower_top()`. The slim dock is always ONE line left of the controls (the design; a two-line dock was rejected on 2026-10-30): `Stage::fit_dock_line` squeezes it as the window narrows (short phrases before the comma, closer spacing, labels become tooltips, then words cut short) and lets it grow back. Its look is round 101's at the user's window size: words in Anton (never bold: GTK makes button text bold, which fakes a heavier Anton) between two grey side bars, a thin red chevron (`stage::chevron`), labels on the words' baseline.
- Sizes follow the design's vw formulas (`Stage::resized` loads them into `fluid_css`: title clamp(42px, 5.2vw, 96px) x 1.2, artist clamp(22px, 2.3vw, 38px) x 1.2, dock words clamp(14px, 1.12vw, 19px) x 1.2). Line heights are given in px: GTK reads a bare number as a share of the font's own (tall, for Anton) line height. The title block sits like the design's `top: 38%; translateY(-54%)` (`Stage::set_anchor`: 33% games, 37% sport) using its real laid-out height (GTK's height-for-width measure of the block comes out taller), and is as wide as its content up to 44% of the width. Songs show the credits grid; films, series, games and sport show one "year · app" line instead (`Head.line`).
- The room's screen (`has_monitor`: game, film, TV) shows the logo or title for 3 s; then a game plays its trailer once, muted, and films/series go straight to their stills (TMDB backdrops also fill `Meta.pictures`); their trailer only plays on the play button. `oys::Scene.corner` is the top-right corner's box: the other themes shrink their wall screens to stay clear of it.
- Films and series get a ticket band across the top (`stage::Ticket`: Admit one, app · screen, the source, a barcode from the title, the outlined speaker count) in place of the kicker and the big number; `Stage::corner_rect` then returns the band's right end. A match title ("Home v Away") puts a scoreboard on the room's screen (`page::teams`, three-letter names). The title and artist labels are capped to the title block's width (`Stage::fit_title_width`), or a wrapped label asks for its whole text on one line.
- `MediaFile::clear()` on a stream still opening trips a GLib critical in GTK's GStreamer backend, so `stop_video` only clears prepared streams. A screenshot taken while a layout is pending (a video just started) renders nothing: `main::screenshot` returns false and the shot retries on later frames.

- `room::SPEAKERS` is ordered FL,FC,FR,LFE,RL,RR; `meters::ORDER` is FL,FR,FC,LFE,RL,RR. Map between them with `ch_index`.
- "Stereo plays on" (`stereo_on`: front | rear) is applied per stream with `pw-cli set-param ... Props` channelmix params (`simple` upmix, `fc-cutoff` 0 so the centre stays silent). "All" (centre too) was removed on 2026-10-27: PipeWire fills the centre with L+R (3 dB above each front, no level setting; `fc-cutoff` low-passes at about half its value), which sounded hollow/coloured on stereo recordings; saved "all" migrates to "rear". `system::apply_streams` skips nodes named `sbcommand*` except `sbcommand.relabel.out`; the speaker test stream is named `sbcommand.test` so it is never changed mid-play.
- **Each kind of content keeps its own sound** (user, 2026-10-30): `model::KINDS` (music, film, tv, game, sport, video, stream, each with the activity whose profiles it uses), `Settings.kind` (the kind the sound is set for) and `Settings.kinds` (`KindSound`: profile, EQ, tone, stereo_on, SBX on). `set_kind` applies one; `remember_kind` stores the sound in use, and is called ONLY from your own changes (`Ui::set_style`, `set_sbx`, `set_stereo_on`, `pick_eq`, the page's tone, the tray's `edit`), never from automatic switches (genre EQ, app memory). Something new playing goes through `Settings::switch_for` (the kind's sound, then `recall_app`, then `follow_game`), in the window (`on_detected`) and the background service (`background_switch`); the kind comes from `meta::kind_of_detection` (no lookups). The Sound tab's kind picker (`kind_dd`) plays another kind's sound to hear and change it; closing ☰ goes back to `playing_kind`. The tray lists the seven kinds.
- **Several apps at once** (user, 2026-10-30: music beside a game sounded "rubbish like the game"): the card has ONE DSP (SBX, EQ), so: `detect::pick`/`main_of` choose what sets the card by rank (game > film/TV/video > music, newest among equals); `system::apply_streams` gives every other app its own kind's "Stereo plays on" and an EQ inside its stream (PipeWire 1.6's per-stream `audioconvert.filter-graph.0`, ten `bq_peaking` an octave wide; `model::stream_sound` = its kind's curve minus the card's, so after the card's EQ it hears its own), set live, nothing restarts, cached per node; `null` removes it. While music plays beside a game the card's effects are eased for both (`Settings.blend`, not saved, `model::beside_fx`: Surround halved, Smart Volume off unless Scout). Games and players start and stop their streams often, so the background service holds it steady (`detect::BesideGame`: on after 4 s of both, off after 10 s without) and leaves a flag file (`~/.cache/sbcommand/beside-game`) that `worker::apply` reads in every process; it first flapped every few seconds. Until something new plays, `Settings.kind` is taken from what's playing (window and service), or each app's own sound would stay off. The background service re-applies both when what plays changes. `Settings.per_app` (Settings → "Each app its own sound") turns it off. Tested silently on a null sink (a +12 dB band at 1 kHz measured exactly; the app's own 10-band text on both channels); never test it on the user's playing streams without asking.
- SBX profiles and EQ presets are Creative's exact values from Sound Blaster Command 3.4.98.00 (installer `SBZMasterInstaller_3.4.98.00.exe` from support.creative.com, which needs a captcha, so the user downloads it; Inno Setup, unpack with `innoextract`), files `commonappdata/Creative/SBCommand/Product/ZxR/{Profiles,Presets/EQ}/*.json`. In profiles, Settings `Type` 0 = Headphones, 1 = Speakers (the `OutputType` enum in `Creative.Platform.Profiles.dll`); EQ files say "Speaker"/"Headphone". Levels are 0-1 there. Don't commit Creative's files, only the numbers. "Music" is this app's own (Creative has none); so is "Arena", the music Room for a stadium gig (user, 2026-10-30: stadium "not bassy enough"): Creative's "Stadium" is made for watching sport (Bass off, Smart Volume 74, Dialog+ on for the commentary), so sport keeps it and live music uses Arena (wide, Crystalizer 45, Bass 65, no Smart Volume or Dialog+); settings version 5 moves a music "Stadium" to Arena. With a sub and bass redirection, the SBX Bass boost (through the EQ) reaches up to the speakers' crossover (140 Hz for the DTT2200), not just Creative's 80 Hz Bass crossover, so it uses the sub's whole range (`model::bass_boost`). "Rock (classic)" is the driver's older Rock. The user prefers Creative's **Rock** (said 2026-10-30; an earlier note had it the other way round and settings version 4 moved saved "Rock" to "Rock (classic)"): rock genres map to Rock and settings version 5 moves saved "Rock (classic)" back to Rock (EQ slots, per-activity, per-kind, per-app memory). Creative's 14 game profiles (and their EQs) are picked by `Settings::follow_game` when that game is detected, unless per-game memory has the user's own choice.
- No 5.1 / 2.1 listening switch (removed 2026-10-27 at the user's request): 5.1 already plays stereo on the fronts (or + rears) and 5.1 sources on all six by itself, so the switch only forced films onto the fronts. `Settings.listen` stays for old settings files and is always "51". Owners of 2.1 speakers pick 2.1 in Speaker setup, which selects PipeWire's analog-surround-21 profile (PipeWire downmixes 5.1 sources).
- Pure = SBX off: the five SBX effects (Bass and Scout included) are off and their knobs grey out; the equaliser stays on, as in Creative's app where SBX and the EQ are separate switches (user's choice, 2026-10-27).
- The tray (ksni) runs in the `watch` process and may fail to register in the first seconds after login; the watch loop retries.
- The Spotify Flatpak labels its stereo `aux0,aux1`; `relabel_aux_streams` moves such streams through the `sbcommand.relabel` loopback so they can be placed.
